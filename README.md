# VoiceAgent

Голосовой ассистент для Android (OnePlus 13, рутован) с оффлайн-распознаванием
речи (Vosk), двухступенчатым LLM-мозгом (DeepSeek + Claude, только по API,
без единого сервера — всё работает прямо с телефона), управлением через
AccessibilityService и root, записью/суммаризацией лекций и Telegram-ботом.

## Быстрый старт

1. Выполни `python3 scripts/prepare_vosk_model.py`: скрипт скачает русскую
   модель Vosk с сайта разработчика, проверит SHA-256 и подготовит её для APK.
   Модель занимает десятки мегабайт и не хранится в Git.
2. Открой проект в Android Studio и собери приложение. При сборке через GitHub
   Actions модель подготавливается автоматически.
3. После установки введи ключ DeepSeek в настройках приложения. Claude и
   Telegram можно настроить там же; ключи в APK не встраиваются.
4. При первом запуске:
   - разреши запись аудио и уведомления;
   - включи Special Access → Accessibility → VoiceAgent (для управления экраном);
   - включи Notification access (для чтения входящих уведомлений и быстрых ответов);
   - для root-команд (вайфай/блютус) разреши доступ в KernelSU/Magisk при
     первом запросе.

## Получить .apk без Android Studio

Нет компьютера с Android Studio под рукой — есть автосборка через GitHub
Actions (`.github/workflows/build-apk.yml`):

1. Залей проект в свой репозиторий на GitHub (`git init`, `git add -A`,
   `git commit`, `git push` — можно прямо из Termux).
2. Открой вкладку **Actions** в репозитории — сборка запустится сама
   при пуше в `main`, либо запусти вручную кнопкой "Run workflow".
3. Через пару минут в списке запусков будет готовый артефакт
   `voiceagent-debug-apk` — скачай и установи на телефон (разреши
   установку из неизвестных источников, если попросит).

Это debug-сборка (без подписи релизным ключом) — для личного использования
достаточно. Ключи (DeepSeek/Claude/Telegram/MAX) в неё не зашиты — вводятся
после установки прямо в Настройках приложения.

## Backend-воркер (опционально — только для тяжёлых 3D/рендер-задач)

`backend/` — тонкий FastAPI-сервис-очередь для задач, которые не потянуть
на телефоне. **Важно: на Android-стороне пока нет кода, который бы с ним
разговаривал** — ни поля в Настройках, ни клиента, отправляющего задачи.
Это только серверная часть-заготовка (см. `run_job_stub` в `server.py` —
подставь свой исполнитель: рендер, тяжёлые вычисления и т.п.), интеграцию
с приложением ещё предстоит написать, если она понадобится. Для обычной
работы Вани (голос, чат, генерация кода, сценарии) backend не нужен вовсе —
DeepSeek/Claude вызываются прямо с телефона, напрямую.

```
cd backend
cp .env.example .env   # впиши свой AGENT_WORKER_TOKEN
pip install -r requirements.txt
python -m uvicorn server:app --reload
```

Приложение — `app` внутри `server.py`, поэтому модуль в команде запуска —
`server:app`, а не `main:app`. Через Docker то же самое:
`docker compose up -d` (сам подтянет `.env` из этой же папки).

`AGENT_WORKER_TOKEN` в `.env` — это просто секрет для авторизации перед
самим воркером (проверяется в `server.py`), не ключ DeepSeek/Claude.

## Архитектура

- `core/` — STT (Vosk), TTS, клиент LLM (DeepSeek + прямой Claude), шина событий, foreground-сервис.
- `system/` — AccessibilityService (тапы/свайпы/чтение экрана), root-переключатели
  (`RootActions`), быстрый ответ на уведомления, диагностика, автозапуск при включении.
- `agent/` — AgentOrchestrator: транскрипт → LLM → либо голосовой ответ, либо JSON-действие.
- `lecture/` — запись лекций, чистка транскрипта, суммаризация через LLM, хранение.
- `integrations/messenger/` — Telegram (Bot API), MAX (bot API), WhatsApp (Business Cloud API, официальный).
- `integrations/bot/` — foreground-сервис, который держит поллинг Telegram живым.

Ничего из этого не требует отдельного сервера на ноутбуке или VPS — весь код
живёт и выполняется на самом телефоне; единственные внешние вызовы — к API
DeepSeek/Claude/Telegram напрямую по HTTPS.

## Новое: генерация кода голосом и авто-подхват токена от BotFather

Теперь можно сказать вслух что-то вроде:
> «Напиши код для тг-бота, который сможет по ссылке давать мп4 или мп3 файлы,
> а ключ возьми у BotFather в моём Telegram»

Как это работает по шагам:

1. LLM в `AgentOrchestrator` распознаёт запрос как `generate_code`, превращает
   его в чёткое ТЗ и вызывает `devassist/CodeGenAgent.kt` — тот генерирует
   небольшой проект (обычно 1-4 файла) через тот же DeepSeek API.
2. `devassist/ProjectStorage.kt` сохраняет проект локально и кладёт .zip в
   Загрузки (`Download/VoiceAgent/`), откуда его видно в Termux
   (`~/storage/downloads/` после `termux-setup-storage`).
3. Если проекту нужен `TELEGRAM_BOT_TOKEN`, агент это озвучивает и включает
   "ожидание токена": `system/NotificationReader.kt` +
   `integrations/messenger/TokenCapture.kt` следят за уведомлениями от
   @BotFather в Telegram и регекспом достают токен вида `123456:AAE...`.
4. Найденный токен **не применяется автоматически** — агент вслух спрашивает
   подтверждение ("Использовать его?"), и только услышав "да", сохраняет токен
   в зашифрованное хранилище (`core/security/SecretsStore.kt`, на базе
   Jetpack `EncryptedSharedPreferences`). Посмотреть/скопировать его можно на
   экране "Ключи и найденные токены" (`SettingsActivity.kt`).
5. Само выполнение кода агент на себя не берёт — он не запускает
   сгенерированный проект автоматически. Вы сами открываете zip в Termux и
   запускаете (`pip install -r requirements.txt && python bot.py`), экспортируя
   токен из шага 4 в переменную окружения. Это осознанное ограничение: голосом
   удобно попросить код и подтвердить передачу токена, но незаметный
   автозапуск сгенерированного кода с реальным API-ключом — не то, что должно
   происходить без вашего явного участия.

Готовый пример именно такого бота (принимает ссылку, качает mp3/mp4 через
`yt-dlp`, токен только из переменной окружения) лежит в
`examples/telegram-media-bot/` — можно смотреть как референс или просто
запустить как есть. Там же — короткая заметка про авторские права: скачивать
стоит только то, на что у вас есть права, свой контент или явно разрешённые
источники.

## Чек-лист перед первым запуском на реальном телефоне (OnePlus 13)

Собран по результатам полной проверки проекта — по шагам, в порядке, в котором
реально стоит их делать, чтобы не упереться в одно и то же дважды.

1. **Открой в Android Studio.** Если увидишь запрос "Gradle wrapper not
   found — create one?" — соглашайся, это нормально (в архиве нет бинарного
   `gradle-wrapper.jar`, чтобы не тащить в zip лишний бинарник; сам скрипт
   `gradlew` тоже придётся сгенерировать через IDE или `gradle wrapper`,
   если Gradle установлен локально).
2. **Впиши ключи в `local.properties`** (`DEEPSEEK_API_KEY` — обязательно,
   остальные — по необходимости для соответствующих функций).
3. **Скачай Vosk-модель** (`vosk-model-small-ru-*` с alphacephei.com/vosk/models)
   и распакуй в `app/src/main/assets/model-ru-small/`. Без этого шага голосовой
   ввод не заработает вообще, а по логам это не всегда очевидно — после сборки
   зайди в Настройки → «Диагностика» и проверь пункт «Оффлайн-модель
   распознавания речи».
4. **Настройка входа через Google** (экран-замок при открытии приложения) —
   единственный шаг, который нельзя сделать только правкой кода, нужен
   Google Cloud Console:
   - `./gradlew signingReport` (или в Android Studio: Gradle → app → Tasks →
     android → signingReport) — скопируй SHA-1 для варианта `debug`.
   - В [Google Cloud Console](https://console.cloud.google.com/) создай
     проект → Credentials → Create Credentials → OAuth client ID → Android.
   - Package name: `com.voiceagent.oneplus13`, SHA-1: тот, что скопировал.
   - Без этого шага при нажатии «Войти через Google» будет ошибка
     `DEVELOPER_ERROR` — теперь она отображается прямо на экране входа
     текстом, а не молчаливым зависанием, и там же есть кнопка «Продолжить
     без входа», чтобы это не заблокировало доступ к твоему же приложению,
     пока не настроишь вход.
5. **Установи и открой приложение на телефоне**, затем сразу зайди в
   Настройки → «Диагностика» — экран проверит микрофон, Accessibility,
   доступ к уведомлениям, оверлей, оптимизацию батареи, ключ DeepSeek и
   Vosk-модель одним списком с кнопками "Открыть настройки" на каждый пункт.
   Голосом то же самое — «Ваня, всё работает?».
6. Включай разрешения в порядке из списка «Диагностика» сверху вниз — обычно
   именно микрофон и Accessibility нужны раньше остальных, поэтому они и
   стоят первыми.
7. OnePlus (ColorOS) особенно агрессивно выгружает фоновые процессы — пункт
   «Оптимизация батареи» в диагностике не косметический, без него голосовой
   сервис может самопроизвольно останавливаться через какое-то время после
   блокировки экрана.

## Другие улучшения в этой версии

- **Диагностика** (`system/Diagnostics.kt`, экран в `SettingsActivity` +
  голосовая команда «всё работает?») — самопроверка перед тем, как что-то не
  сработает молча: микрофон, Accessibility, доступ к уведомлениям, оверлей,
  оптимизация батареи, ключ DeepSeek, наличие Vosk-модели — с прямой кнопкой
  в нужный системный экран для каждого проблемного пункта.
- **`<queries>` в манифесте** — на Android 11+ без этого блока
  `SystemController.openApp` («открой Телеграм») почти всегда молча ничего
  не делает из-за ограничений видимости пакетов; раньше это работало бы в
  теории, но не на настоящем телефоне.
- **Google-вход больше не может намертво запереть** — при ошибке настройки
  (чаще всего незарегистрированный SHA-1) экран входа теперь показывает
  причину и даёт кнопку «Продолжить без входа», вместо того чтобы просто
  ничего не делать по нажатию «Войти».
- **Экран разрешений** в `MainActivity`: кнопки сразу ведут в нужные системные
  настройки (Accessibility, доступ к уведомлениям, отключение оптимизации
  батареи), чтобы не искать их вручную.
- **Экран настроек** (`SettingsActivity`) — ключи DeepSeek/Telegram/MAX можно
  менять без пересборки приложения; они хранятся в зашифрованном виде и имеют
  приоритet над значениями из `local.properties`.
- **Ретраи в LLMClient** — временные сетевые сбои (5xx, обрыв соединения)
  повторяются с небольшой задержкой вместо мгновенного падения команды.
- **Диалог подтверждения** в `AgentOrchestrator` — универсальный механизм
  "да/нет", уже используемый для токена BotFather, но подходящий для любых
  будущих действий, требующих явного согласия перед выполнением.

## Важно

- WhatsApp-клиент использует официальный Business Cloud API от Meta — для неофициальных
  библиотек (веб-скрапинг WhatsApp Web) есть риск блокировки номера, поэтому такой подход
  сюда не включён.
- Ключи из `local.properties` пробрасываются в `BuildConfig` при сборке — не коммить этот
  файл в git (уже добавлен в `.gitignore`).
- Это рабочий каркас архитектуры, а не готовое к продакшену приложение: обработка ошибок,
  ретраи сети и UI сведены к минимуму, чтобы структура была понятной и её было легко
  расширять.
