# Нагрузка VoiceAgent на Android

Проверены горячие участки Android-приложения, JNI, фоновые сервисы и обращения к серверу. За основу взята ветка сборки «Аудит 2» на коммите cc4c5fd. Расход батареи и температура на физическом OnePlus пока не измерены.

| Когда | Что расходовало ресурсы | Что изменено |
| --- | --- | --- |
| Включение голоса | Вспомогательный метод Vosk заводил отдельный executor для распаковки. Сервис не управлял его завершением | Подготовка модели выполняется внутри IO-корутины сервиса. Повторные запуски используют уже распакованные файлы. Остановка дожидается завершения работы перед освобождением модели |
| Ожидание команды и запись лекции | Каждые 200 мс Vosk мог строить промежуточный текст, который обработчик отбрасывал | Распознаватель по-прежнему принимает каждый аудиобуфер и отдаёт целые фразы. Сигнал для блокировки во время озвучки сохранён |
| Выбор локальной модели и генерация | При чтении статистики мог загружаться JNI-модуль. Токенизация вызывалась дважды. CPU-движок без прикреплённого пула создавал временных рабочих для графов | JNI загружается по требованию. Одна токенизация на запрос, один буфер сборки токенов, один пул до конца ответа. Ожидающие рабочие блокируются, число рабочих ограничивает выбранный профиль |
| Сценарии | На обычной реплике перечитывались все JSON-файлы | Общий для редактора и сервиса индекс. После первого прохода промах обходится без чтения файлов, совпадение читает один файл. Сохранение и удаление сбрасывают индекс |
| Уведомления | Android присылал события всех пакетов. Для дайджеста удерживались тексты до 200 сообщений. Для быстрого ответа сохранялось полное системное уведомление | Ранняя проверка пакета, дайджест хранит только источники разрешённых событий. Для ответа остаются адресат и действие Android. Курсор последовательности различает события, пришедшие в одну миллисекунду |
| Настройки и сеть | Несколько клиентов создавали свои сетевые ресурсы. В настройках расшифровывались все проектные токены. Опрос загрузки мог продолжаться в скрытом окне | Общий HTTP-клиент создаётся при облачном запросе. Чтение ключей вынесено с потока интерфейса, проектный секрет читается при копировании. Видимый прогресс обновляется раз в 3 секунды, в скрытом окне опрос приостановлен. Системная загрузка продолжается |
| Память пользователя | При удалении каждого устаревшего временного факта заново пересчитывались слова оставшихся фактов | Слова считаются за один проход. Правила удаления и приоритеты сохранены |

## Воспроизводимые проверки

- WorkflowIndexTest создаёт 20 сценариев, проверяет число чтений на 100 реплик без совпадения, поиск после переименования и удаление.
- NotificationBufferTest проверяет границу 200 записей и доставку событий после получения дайджеста.
- FinalSpeechTest подаёт одинаковый синтезированный русский счёт и тишину двум распознавателям. После прогрева чередует порядок запусков, сравнивает завершённые фразы и выводит четыре значения CPU для каждого варианта. Файл russian-digits.pcm содержит моносигнал 16 кГц, signed 16-bit little-endian, только для инструментального теста.
- LocalInferenceTest запускает настоящий движок с маленькой GGUF и Qwen 3.5 0.8B, проверяет повторное использование весов, тепловые профили, отмену и ограниченный бюджет рассуждения. Это проверка исполнения, для оценки качества ответов 14B или 27B нужна выбранная пользователем модель.

## Оставшиеся ограничения

- При включённом прослушивании микрофон и акустическая модель продолжают работать в ожидании «Ваня». Без этого режим с будильным словом перестанет принимать целую фразу. Во время озвучки декодирование приостановлено.
- При локальной генерации объём весов и число реально сгенерированных токенов по-прежнему определяют основную нагрузку. Весам помогает кэш между соседними запросами. Контекст создаётся заново на каждый запрос, префикс истории пересчитывается. Выгрузка весов после 45 секунд простоя освобождает RAM, но следующий запрос снова загружает модель.
- История открытого экрана чата растёт до закрытия экрана или начала нового чата. Автоматическая обрезка привела бы к потере видимой переписки. Для длительных сессий требуется постраничная история с явным сроком хранения.
- Оркестратор по-прежнему объединяет много команд и состояния, поэтому тесты отдельных компонентов не покрывают все комбинации голосовых, экранных и внешних событий. Эмулятор не воспроизводит прошивку OnePlus, сторонние модули, живые чаты и реальные тепловые ограничения устройства.
- Бэкенд хранит задания и лимиты в памяти одного процесса. Перезапуск теряет очередь. Для запуска нескольких экземпляров понадобится общее надёжное хранилище. Сборки для ручного тестирования имеют отдельный Android-пакет и тестовую подпись CI. Для обычных обновлений на месте нужен постоянный ключ подписи.

## Сравнение на телефоне

1. Для двух сборок выбери один GGUF, одинаковый режим ответа и одинаковый профиль нагрузки. Для сравнения приложение второй сборки должно быть остановлено.
2. С одной яркостью экрана и при одинаковой начальной температуре повтори один и тот же запрос. Отдельно сравни первую загрузку и пять повторов с уже загруженной моделью.
3. В настройках модели запиши время загрузки, обработки запроса, генерации и число токенов. Новая сборка также показывает время CPU всего процесса. Оно складывается по ядрам и может быть больше времени по часам.
4. Для оценки батареи сравни отдельные одинаковые по длительности сеансы ожидания с голосом и без него. Запиши температуру до и после. Статистика отдельного запроса не измеряет энергопотребление за час.
